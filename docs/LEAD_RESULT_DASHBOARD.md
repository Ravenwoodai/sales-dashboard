# Lead Result Dashboard

The reusable weekly workbook is generated by `scripts/build-lead-result-dashboard.mjs`. It is a plain-English overall lead-allocation and approved-sales workload report.

## Local web dashboard

Open `http://127.0.0.1:3000/lead-results-dashboard` after starting Sales Dashboard. The workspace follows the workbook's title/KPI/chart/guidance/manager/performance/check hierarchy and places the complete Performance Rankings table at the bottom of the page.

The date form accepts a range only when the governed allocation population, approved-sales population and applicable call-evidence contracts reconcile for the entire selection. Invalid or out-of-coverage requests are rejected, and evidence-incomplete requests stay unavailable; missing evidence is never displayed or exported as zero. The page lists any known complete range presets.

Every safely backed current-period figure links to a selected-range drilldown through the existing privacy-safe evidence references. Prior-period snapshot fields and any figure without truthful source-level evidence are intentionally non-clickable and explain why. The UI says `Leads Uncalled Within Reporting Window` only when the governed call gate is complete; otherwise it says `Allocated Leads With No Recorded Call by Evidence Cutoff` and preserves the incomplete-negative warning.

The Export XLSX action calls `/exports/lead-results-dashboard.xlsx` with the selected dates. `src/leadResultDashboard.js` builds one shared report object consumed by the UI, drilldowns and `scripts/build-lead-result-dashboard.mjs`; the application does not read data back from XLSX or maintain a second metric implementation.

The workbook deliberately does not report New Business, Warm, unresolved customer-history categories, or allocation-name substitutes. The available governed customer-history index is far too incomplete to support a defensible binary result for every Sent Lead. Those fields may return only after a complete exact Customer ID, order ID and order/approval timestamp contract can classify the full report population and the reporting rule is explicitly approved.

## Source refresh

The Carma Reports project now owns authenticated acquisition of the raw
allocation export. Run it with the exact source week:

```powershell
cd "<path-to-Carma-Reports>"
npm run weekly-allocation:extract -- --start 2026-07-20 --end 2026-07-26
```

The command checks the authenticated weekly-exports index, downloads only the
exact requested filename, validates the required event schema and requested
date bounds, preserves the source bytes, and writes an immutable SHA-256
manifest. It fails closed with a timestamped audit when the source has not
published the requested week; it never substitutes Campaign Quantity or call
rows.

Download the matching weekly call CSV from the same authenticated source page.
Then import the allocation and call pair without altering the raw bytes. Pass the
complete primary call history whenever it has been refreshed; the importer retains
that primary source on later weekly imports instead of replacing it with the weekly
supplement:

```powershell
npm run report:import-weekly-exports -- --allocation "C:\path\WeeklyLeadAllocationExport.csv" --calls "C:\path\WeeklyCallExport.csv" --primary-calls "C:\path\CompleteCallHistory.csv" --start 2026-07-27 --end 2026-08-02
```

The importer:

- validates required columns;
- copies each CSV unchanged to `data/carma/raw/weekly-performance-exports` with a SHA-256 suffix;
- refuses to overwrite different content;
- writes a stable manifest containing observed dates, row counts and hashes; and
- updates `data/store/performance-cohorts.json` with a date-order-aware call-source
  bundle: day-first primary history plus month-first weekly supplement.

Rerunning the same command reports `already_present` and leaves the retained files unchanged.

## Build

```powershell
npm run report:build-lead-result-dashboard -- --output "outputs\lead-result-dashboard-YYYY-MM-DD"
```

Optional arguments:

- `--start YYYY-MM-DD --end YYYY-MM-DD` selects a bounded range inside the configured source period.
- `--previous-snapshot "path\snapshot.json"` explicitly overrides the comparison period. Normally this is unnecessary: the generator automatically selects the newest governed snapshot whose end date is before the current period.

The output folder contains the dashboard XLSX, preview images for every worksheet, `snapshot.json` and `validation.json`. A validated snapshot is also retained under `data/store/lead-result-dashboard-snapshots` so the next fully reconciled report can populate `Prior Sent Leads`, `Prior Approved Sales`, `Prior Allocated Leads Sold %`, `Change` and `Company-Supplied Sales Share Outcome` without manual file maintenance. Legacy snapshots without exact company-supplied sales fields are not used for salesperson share comparison.

The generator fails closed when governed all-approved-sales coverage is not reconciled for the selected period. It will not turn missing sales coverage into a zero-sales result. Fresh allocation/call files can therefore be retained before the matching approved-sales extraction is ready, but the performance workbook is generated only from the newest fully reconciled period.

## Governing definitions

- `Total Sent Leads`: logical allocation events deduplicated by customer, recipient, manager, sent date/time and allocation name.
- `Unique Leads Sent`: unique customer + recipient pairs. Repeated sends to the same recipient count once; the same customer sent to another salesperson creates another pair.
- `Approved Sales`: all reconciled approved orders in the week after configured personnel exclusions. It is not restricted to customers allocated in the same week.
- Manager sales: exact salesperson-label matches only. Off-roster approved sales remain in the complete total and source split, but not in named manager comparisons. `Tim Okeefe`, `Robert Moricky` and `Andrew Ross` are excluded centrally from allocation, call and approved-sales reporting along with the existing configured exclusions. Personnel exclusions apply only when the excluded person is the primary salesperson/caller/seller; a valid manager label remains visible so included salespeople still roll up to the correct manager.
- `Sales From Allocated Leads`: Approved Sales in the report week where exact Customer ID and exact seller history prove that the customer was allocated to that seller before the sale. There is no allocation-age limit.
- `Sales From Allocated Leads % of Classified Sales`: Sales From Allocated Leads divided by classified Approved Sales (`Sales From Allocated Leads + Self Sourced`) for the same salesperson or team. The result is always displayed. Coverage is `classified ÷ all Approved Sales`; unresolved orders remain explicitly withheld and produce a lower-to-upper possible range. Less than 3% unresolved remains comparable and award-eligible subject to normal sample gates. At least 3% unresolved is labelled `Provisional` and excluded from source-share comparisons and trophies. Weekly Sent Leads are never the denominator.
- Weekly Sent Leads remain a separate current-workload measure. Sales From Allocated Leads may trace to allocations from any earlier week. The workbook does not call their relationship weekly conversion and does not conclude that current weekly leads were wasted.
- `Salespeople Receiving Leads`: distinct eligible salespeople who received at least one valid Sent Lead in the selected period. This is exact from allocation evidence. It cannot identify an otherwise-active salesperson who received zero leads; a governed roster/attendance source is required for that.
- `Sent Leads per Recipient`: manager Sent Leads divided by Salespeople Receiving Leads. The Dashboard adds the weighted company average (`total Sent Leads ÷ total lead recipients`) as a workload reference. The `Lead Distribution` sheet compares each salesperson with their team's equal-share reference using a 25% review band. These are review prompts, not fairness verdicts; capacity, leave, rostered hours and role differences may justify unequal allocation.
- Chart guidance: every Dashboard chart has `How to read`, `What this chart shows` and `What to know`. The narrative is deterministic, names exact data-backed standouts and review points, and uses fixed thresholds: 10% from the manager-comparable Company Supplied Share, 2 percentage points for weekly lead allocation share versus company-supplied sales share, and 25% from team equal-share allocation. The chart titled **Weekly Lead Allocation vs Company Supplied Sales** is a sales-mix comparison, not a conversion rate or a statement that current leads were wasted. The call-backlog chart names the largest and smallest team counts, the total population, the evidence cutoff and the unresolved-call warning without treating the count as a fair performance ranking.
- Call observation uses every available exact call after allocation through the
  displayed latest evidence date. The allocation period selects the leads; it does
  not truncate later call evidence. Older allocations therefore have more time
  available than newer allocations, which is suitable for an operational backlog
  view but must be disclosed before comparing rates.
- Primary and weekly call files are merged with their declared date order and
  deduplicated by `call_id`. For the retained 20-26 July period this restores the
  available 20-21 July primary history that the weekly supplement omitted.
- Utilisation/follow-up and authoritative `Not called` are suppressed unless every
  allocation date is covered and every potentially relevant unique call has a valid
  exact customer ID, salesperson and timestamp. Direct `customer_id` is primary. A
  blank value may use `FoundCustomerID` only as positive evidence when it exactly
  matches the same salesperson's selected-period allocation and the call occurred
  after allocation. Raw files remain unchanged, conflicts are rejected, and the
  fallback is never used for sales-source classification or a negative finding.
  Missing `customer_id` is never evidence that a call or customer was self-sourced.
- When the call gate passes, `Leads Uncalled Within Reporting Window` equals Unique Leads Sent minus exact post-allocation call-observed customer-recipient pairs inside the governed reporting window. When the gate is incomplete, the same evidence is labelled `Allocated Leads With No Recorded Call by Evidence Cutoff`; it is not proof that nobody called. The label never asserts behavior after the window.
- `Company-Supplied Sales Share Outcome` compares source-mix quantities only. Both periods need at least 100 weekly Sent Leads and at least 5 Approved Sales; a movement of 5 percentage points or more is `Share increased` or `Share reduced`.

Call records are not used for team active headcount in the current source contract because the supplement has no governed manager field and selected-period date coverage is incomplete.

The Checks worksheet reconciles deduplication, `Sales From Allocated Leads + Self Sourced + Attribution Withheld = Approved Sales`, manager/off-roster sales, approved values, lead-recipient manager totals, Lead Distribution row coverage and team Sales From Allocated Leads. Thirty-day cohort conversion remains unavailable until the cohort has matured and the exact customer + seller outcome window is complete.

### Source-attribution exceptions

An order may have a verified approval timestamp while its exact-customer allocation history remains incomplete, or the approval timestamp itself may be unavailable. The report keeps the order and value in the selected-period totals but must not infer Allocated-Lead or Self Sourced from missing evidence. Pre-sale timing remains usable when the approval timestamp is explicit; only source attribution is withheld for incomplete allocation-history coverage. The `Approved Sales`, `Performance Rankings`, `Performance & Trophies`, `Manager Analysis`, `Data Notes` and `Checks` worksheets show the classified-sales percentage, coverage, unresolved count, possible range and `High coverage`/`Provisional` status instead of suppressing the result.

### Customer-ID-free calls and weekends

A valid call without `customer_id` is treated as an unsuccessful self-sourcing attempt unless exact FoundCustomerID, exact normalized salesperson and call-after-allocation evidence positively link it to an allocated customer-recipient pair. The raw call row is not changed. Unlinked attempts are reported separately, cannot become company-supplied lead calls, cannot become Self-Sourced Sales and do not block call scoring. Empty Saturday or Sunday rows are treated as no weekend activity; every allocation weekday must still be covered, and malformed timestamps, missing call IDs or genuine identity conflicts still fail closed.

## Performance, investigation and trophy views

The low-information Best Salespeople and Best Teams panels are removed. The Dashboard and `Performance & Trophies` sheet now show `Salesperson Results Worthy of Investigation` and `Team Results Worthy of Investigation`, with every generated reason displayed in full. A dedicated `Lead Burners` sheet contains the complete top-10 high-allocation/weak-result queue and, only when the call gate passes, the top-10 uncalled-percentage queue.

The visual key is fixed across both sheets: blue section/title and table-header treatments identify individual salesperson results; teal treatments identify manager-team results. Team detail rows also use a pale teal fill, while concern explanations may retain amber to preserve the warning meaning. The colour key is stated in plain English on both sheets so the distinction does not rely on colour alone.

- A team is every eligible salesperson carrying the same exact Manager label. Team counts are summed first, then every rate divides the aggregated totals; salesperson percentages are never averaged.
- Team totals show Salespeople Receiving Leads, weekly Sent and Unique Leads, reallocations, Approved Sales/value, Sales From Allocated Leads and Self-Sourced Sales, company-supplied share, weekly lead share, company-supplied sales share, context-only workload ratios and the Company-Supplied Sales Share Index.
- A manager's own salesperson activity is included only when their salesperson and Manager labels genuinely match. The detailed table shows the manager's own Sent Leads, sales, value and share of team sales separately.
- Source-share investigation comparisons require at least 100 weekly Sent Leads and 5 Approved Sales. Count-based Sales From Allocated Leads awards retain the factual eligible leader.
- Lead Burners high-allocation/weak-result candidates require at least 100 weekly Sent Leads and comparable source attribution. Uncalled candidates require complete call coverage and at least 25 allocated customer-recipient pairs. Both queues are deterministic investigation prompts, not disciplinary findings.
- Policy-withheld, unknown and unidentified team labels cannot receive named team awards.
- Self-Sourcing trophies count Self-Sourced Approved Sales and contributing salespeople. They do not claim a self-sourced-lead count or conversion rate because that denominator is unavailable.
- `Company-Supplied Sales Share Champion` and `Sales From Allocated Leads Champion` replace the former allocated-lead trophy labels.
- `Versatility Champion` is awarded to the eligible salesperson or team closest to a 50/50 split of company-supplied and Self-Sourced classified Approved Sales. Both sources and at least 12 classified Approved Sales are required.
- `Most Improved` is removed.
- `Lead Utilisation Champion` requires at least 12 Approved Sales and complete call coverage.
- `Consistency Champion` uses the smallest absolute week-over-week percentage change in Approved Sales. Current and prior periods must be contiguous and equal length, and both must contain at least 12 Approved Sales.
- Utilisation and follow-up trophies are scored only when every allocation weekday is covered and genuine call identity/timestamp checks reconcile. Empty weekends and separate Customer-ID-free self-sourcing attempts do not block.

## Weekly call activity

`Performance Rankings` and `Call Coverage` include deduplicated reporting-period calls, outbound calls, average and median `call_duration_seconds`, total call hours, zero-duration calls, short calls (over 0 and under 30 seconds), long calls (at least 300 seconds), and calls per Approved Sale. Duration is activity context and does not prove a human conversation; calls per sale is a workload ratio, not a causal conversion rate.

The Checks worksheet additionally proves team Sent Leads, Approved Sales and Sales From Allocated Leads reconcile to the underlying populations; salesperson and team uncalled/no-recorded-call counts reconcile to the same allocation-pair population; every team share is derived from aggregated counts; manager-own activity is a subset of its team; incomplete calls cannot produce a call trophy; excluded personnel are absent; the utilisation gate is 12 sales; Most Improved is absent; unnamed teams cannot win; and eligible awards show the required runners-up.
